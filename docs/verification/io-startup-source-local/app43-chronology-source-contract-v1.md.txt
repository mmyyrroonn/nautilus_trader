Tests run their own actual numeric127.0.0.1 HTTP and WS clients against the normal server. They never invoke `hl_action`, `hl_execute`, or `hl_fill` directly and do not import native code or manufacture Cache/Portfolio events.

1. Entry plus reduce-only close execute while both raw publications are pending. ACK identity/full quantity, prepublication real account quantity, exact status, deliberately unavailable raw fill history, and eventual raw WS/HTTP equality are checked. The two pending executions must have distinct OID/TID. Terminal/fill times and prior position/fee remain exact. Final true account position is zero without delayed double application.
2. Rejected entry creates no executed order/fill or Filled ACK.
3. Cleanup rejection preserves its already executed/published actual entry and refuses the attempted close without phantom executed facts.
4. Missing response produces no ACK/phantom order/fill and leaves actual account state unchanged. This is fixture correctness only, not proof that a production lost response is safe.

All client reads use bounded transport observation. Negative cases observe the original delay horizon with a finite200ms missing-frame bound; this is not a changed native/action/recovery timeout.
