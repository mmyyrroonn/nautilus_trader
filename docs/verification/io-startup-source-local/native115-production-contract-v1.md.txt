and default perpetual/spot paths retain their existing unbounded account request

selected proof map (including original precision, isolated mode, actual leverage,

context; the normal first Engine binding updates it once. Neither operation
constructs a full account source or promotes financial readiness. Changing this
context discards any old account seal. The worker never reads an Rc Engine Cache.

held. Legacy ordinary publication can still succeed without a seal. The optional

## Read-only diagnostic schema

The normal execution scope JSON adds `startup_private_ingress` with actual
`generation`, `epoch`, `received_sequence`, `is_applied` sampled under the
production ingress guard. `startup_account_source` is the original stored seal
or null. A stored source can remain visible after an identical frame while being
ineligible; its diagnostic presence is not a reuse permission.

Seal fields are policy, generation/epoch/received_sequence, account_revision,
hard_revision, verification_started_ms/verification_finished_ms,
http_source_time_ms/http_received_time_ms, private_facts, native_http, metadata,
spot_metadata, metadata_context, sources and the original account_facts.
`sources.original_sources` contains actual `{request_json: String, received_ms:
uint, raw_text: String}` records; successful sealing has no unavailable requests.
`private_facts` contains exact-string financial values and position facts, actual
receipt/source times, acknowledgement bits and stream epoch. None of these
diagnostics replaces normal Cache or application Portfolio authority.
