Normal owned fills previously invalidated the startup account seal and made every io warm query read role, mode and collateral metadata again. Native117 retains a separate optional original nonfinancial source across validated owned financial changes; every warm query still obtains actual current financial and order facts.

## Original source creation and reuse

The source is created only from a qualified complete original eight-source HTTP transaction after normal selected metadata has been bound to ordinary Engine instruments. The earlier prebinding refresh cannot be sealed later by copying new context. A successful complete full warm read may create a replacement source within the same original recovery deadline. Missing or crossing observations can legitimately leave a run unsealed.

The source binds the original account/address, reader generation and epoch, hard revision, policy, HTTP/Engine metadata pair, actual requests/raw bodies/receipt times, original verification start and finish, and absolute expiry. Owned financial changes invalidate the private financial/startup seal while retaining this separately qualified nonfinancial group. Identity, policy, metadata, reader or hard-source changes invalidate it. Reuse neither creates a seal nor renews its original expiry.

The composed account expires at the original earliest verification start plus the unchanged 2,000 ms maximum age. Metadata keeps its original 30,000 ms expiry. These are finite previous non-atomic role/mode observations; an unrequested silent venue change is not continuously observable authority.

Every composed warm flight requires fully applied current ingress and an unchanged captured sequence through its reads and final owner commit. It validates current run-owned native Cache orders/trade IDs/commissions and ordinary Engine instrument witnesses. Taint, unknown/foreign/cold state, immutable recovery debt and projection barriers remain refusals. Expired or missing prerequisites select actual full reads; a source changed during an already captured flight refuses that flight without starting a new deadline.

## Current financial facts and commit boundary

Every warm flight requests actual io clearinghouse state, frontendOpenOrders(io), unfiltered userFills, and exact active owned CLOID statuses. Missing current leverage rows, including flat accounts, require two repeated actual activeAssetData counterproofs for each selected instrument lacking current position leverage evidence. Previous quantities, a private frame, or Cache zero cannot replace these current reads.

Original prerequisite start/finish/receipts and actual new financial receipts remain separate in diagnostics and AccountState provenance. No public command or application proof flag is added. Source-derived request weights describe a possible reduction, not a measured limiter balance or a liveness guarantee.

The unchanged 3,000 ms total recovery deadline begins before added copies, serialization and lock waits. Lock order remains ingress → account → execution. Candidate construction and heavy report work precede final scalar time qualification; the boundary is sampled after durable persistence/fsync and before publishing AccountState/Ready or releasing reservations. Expiry restores the original reserve and yields Unknown. Final scalar checks use captured absolute metadata and original prerequisite expiry rather than another heavy reconstruction after an early sample.

## Bounded failed-source retention

At most one original prerequisite raw group and one active new raw group are retained, each under the existing 4 MiB collection bound. Shared immutable Arc objects avoid a third historical raw copy. This conservative 8 MiB raw-group bound is not a total process RSS or parsed JSON allocation claim.

Each HTTP body remains at most 1 MiB; the actual escaped serialized JournalFacts record remains at most 1 MiB; cumulative journal storage remains at most 16 MiB. These bounds are separate. On a failed composed flight, durable debt retains reconstructible original prerequisite provenance and actual newly received sources with their distinct clocks. Stop/drop/reopen does not clear that debt. Over-limit retention records a bounded explicit RetentionFailed/incomplete-retention refusal; actual persistence failure taints the journal. Old journal decoding remains compatible.

## Immutable economic demand boundaries

`economics_scope.rs::record_unrequested_history` uses the unchanged actual callback time, clipped by the policy's original finite window. For each exact generation/epoch/endpoint it starts after the greatest prior COMPLETE boundary or an exact zero-page/zero-record warm Unknown boundary. Other readers, endpoints, diagnostics, page-bearing and record-bearing rows cannot qualify that frontier.

Prior coverage, source/consumer receipts, fills and raw fees remain immutable. New disjoint zero-page/zero-record Unknown tails are appended; they do not become requested or COMPLETE history. Identical or earlier boundaries are true byte/revision no-ops. Existing taint is checked before a no-op and is never cleared. Both endpoint additions are staged in one candidate and committed once under the unchanged `history_max_pages * 3` cap; if the second endpoint cannot fit, neither staged row is persisted. No compaction or capacity increase is used.
