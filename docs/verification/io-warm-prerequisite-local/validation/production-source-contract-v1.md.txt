## Original and composed sources

The new optional `WarmPrerequisiteSourceSeal` is distinct from native115's `FullAccountSourceSeal`. Only an actual fully qualified complete account transaction with the normal preexisting metadata and HTTP/Engine binding can create it. The early prebinding connect refresh cannot retrospectively mint a source when binding later arrives. The existing postbinding recovery account refresh can create both original seals while its actual ingress/account guards are held. A successful full warm transaction can prepare a new source and install it only after the ordinary owner commit. A reused warm transaction cannot create, renew or replace it.

Diagnostics expose `warm_prerequisite_source` and `last_query_reused_prerequisite`. Source fields include actual original generation/epoch/sequence/hard revision, account/address/policy, metadata context with ordinary HTTP/Engine binding, original start/finish, `maximum_age_ms`, `effective_expires_ms`, original account HTTP source/receipt, and `sources.original_sources`. `account_source_start` selects the exact eight complete account responses inside a warm collector that also retains actual open/fill/status prefix and leverage-counterproof suffix responses. Complete account observations follow the existing role, two abstraction requests, metadata, spot metadata, full clearinghouse and repeated abstraction requests. Reuse omits the seven old nonfinancial reads and always obtains a new full clearinghouse response.

The prerequisite remains eligible only in the same normal reader/lifecycle, hard revision, account, policy and unchanged metadata context. Financial-only invalidation clears the full financial startup seal while retaining the original optional nonfinancial object. Hard invalidation, stream rebinding or new metadata context revokes eligibility. Every new warm flight independently captures and rechecks the actual current applied ingress sequence, account/execution revisions, private facts, ordinary Cache/Portfolio-derived owned order/fill/fee evidence and exact native instruments. A changed frame during the new flight still refuses that flight, including an identical applied frame. Retaining an object diagnostically is not a Ready or funds grant.

Fresh orders/fills/exact owned statuses and actual full financial HTTP are preserved. Selected symbols missing actual leverage evidence in the fresh full clearinghouse still require two genuine activeAssetData counterproofs. Old metadata source time, leverage, capacity and mark are not renewed. Reused source-based minimum weights are44 for a positioned one-CLOID flight and84 for flat one-CLOID with two counterproofs; zero-CLOID flat is82. These are source arithmetic, not measured token balances or a paired-liveness promise.

Original prerequisite role/mode evidence is explicitly bounded and non-atomic. Unrequested silent remote role/mode changes are not observed by a financial-only flight and must not be described as continuous current authority.

## Clocks, ownership and capacity

`begin_warm_query` captures the existing recovery deadline before any guard acquisition, heavy copy or serialization. An already pending identical query is coalesced without updating that original flight's deadline. Original source expiration is its actual earliest account-group start plus the existing maximum age; reuse does not extend it. Warm account observations retain that original start while recording actual new financial start/source/receipt separately.

Owner qualification prepares all candidate copies before its final clock checks. Reservation absorption uses the existing durable journal path. The original3s deadline, original2s source expiry and current private/metadata freshness are checked again after the actual persistence and heavy native-instrument comparison. A late failure restores the original reservation and refuses AccountState/Ready. Commit keeps the original ingress/account/execution guards; no synthetic financial event, hidden callback, production test hook, cold Cache bridge or debt clearing was added.

Raw records use immutable `Arc` sharing. The original115 full seal and new prerequisite share the same original group; detached group copies share individual immutable raw records. The active group retains its own normal bounded responses. This avoids a third retained deep raw-history copy; it is not a whole-process allocation or RSS assertion.

Existing limits remain unchanged:1MiB per HTTP body,4MiB per accepted HTTP raw group,1MiB escaped serialized JournalFacts,16MiB cumulative journal; account2s, recovery3s and normal quota limits remain unchanged. No provider, deadline or quota was relaxed.

## Durable failed composition

`UnknownSources` retains actual new query `original_sources` and unavailable-source context under the captured new identity. Optional `reused_prerequisite_source` embeds the complete original object, including original request JSON, actual receipt and original raw text. Old raw is not relabeled as new financial source. This representation remains reconstructible after normal stop/drop and does not depend on process Arc lookup or a new external blob store.

If escaped old-plus-new Facts exceed the original1MiB bound, the existing refusal path persists a small explicit `RetentionFailed` record and captured original-origin diagnostic with `raw_retention_complete:false`. Successful bounded refusal remains Unknown and is not automatically called tainted. If the bounded refusal itself cannot fit, or the existing persistence path fails, the original taint/error behavior remains. No incomplete record claims complete raw retention.
