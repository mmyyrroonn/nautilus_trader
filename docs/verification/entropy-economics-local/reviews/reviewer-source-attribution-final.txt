## Origin-generation finding and actual source resolution

The initial frozen source sampled current identity before a getter that independently read its latest generation. An old generation-1/epoch-0 frame could therefore borrow a newly verified generation-2/epoch-0 context across replacement. This was reported as an origin-binding defect, without claiming a report could authorize trading.

The revised actual getter accepts expected_origin from the captured source tuple. The state getter verifies attribution_generation against that expected source generation; actual reader identity must equal the expected tuple before and after the detached account-state copy. Both WS actor and each history page obtain this origin-bound proof before computing current. They recheck source identity after phase-A persistence, and the actor checks again before legacy native projection/accepted-fee hook. The same-epoch replacement test explicitly makes a generation-12 context fail to certify source 11 while allowing source 12 and preserving funds trusted=false. No invented generation DTO or forced proof flag was added.

This fixes the reported cross-generation-context interleaving. Detached historical facts remain source-tagged and report-only; source replacement does not make a report current account proof. Actual test execution on this revision remains pending independent binary/wheel review.

## Boundaries verified by reading actual code

- Default AccountScopeState::invalidate clears attribution_generation and attribution_universe before normal funds invalidation. `invalidate_financial` retains only an existing context while incrementing the same account version and closing funds proof. It cannot create context or mark money/flatness trusted.
- Complete valid WS position changes take the typed financial path. Missing/wrong user or dex, malformed complete snapshot and invalid source time use the default path and revoke context. A refresh starts by clearing context, so position events during pending HTTP cannot reconstruct it.
- HTTP refresh installs attribution only after role, both abstraction facts twice, canonical collateral/native universe, complete scoped financial parsing, verification/source freshness, captured account version, current epoch/active stream and reader generation checks. WS position reconciliation must also succeed. Failed role/mode/collateral or stale/superseded HTTP completion cannot install a usable context.
- HTTP context setup preserves delisted coins in the position universe but excludes them from current active attribution. Candidate cached native IDs are intersected with the latest successfully verified active coin set. A cached ID alone does not establish current membership.
- The getter deliberately does not compare current account version to the establishment revision: typed position/financial invalidation must advance that version to reject old funds HTTP completions while preserving metadata identity. It checks existing attribution generation, actual active stream/epoch, all private ACKs, HTTP source/receive/verification-start TTL, latest complete private receive TTL and optional real private source TTL.
- The returned account snapshot is the original diagnostic snapshot. Its trusted and flat fields are not overwritten. ScopeEvidence separately records attribution_verified and genuine funds trusted. Exact owner/io/inferred disabled mode/canonical USDC/native instrument checks and source-epoch filtering remain in the funding/fill parser. No account funds, order admission or native recovery barrier consults attribution_verified.
- Each history page now obtains fresh attribution after its actual body/quota acquisition; it no longer reuses one proof captured before earlier pages. An unknown/unattributed earlier page clears context, so later pages cannot borrow that earlier context. Already persisted strong identical facts may preserve an independently valid funds proof; report receipts/totals do not participate in that decision.
- For financial WS/HTTP input, funds close before phase-A disk work. `attribution_complete` is true only for nonempty correctly attributed funding/fill_fee observations with supported identity quality, exact io/USDC/instrument/time/amount and verified context. Valid weak funding can preserve attribution while remaining excluded from recognized cash. Unknown, conflict, ledger or failed preservation clears context. Supported empty snapshots retain only an existing context and never establish one or assert positive financial identity.
- A raw frame is saved before typed parsing. `legacy_parse_succeeded` must be true before native owned-fill projection and accepted-fee hook; malformed numeric/schema/duplicate-known-key input remains raw -> Error -> marker. Strict original user/userEvents fills support now exists without inventing an echoing user, and raw startup validation permits that exact original channel variant.
- Economic report consumption performs no AccountState/native fill/balance adjustment and does not clear the #101 native projection recovery barrier. Native application remains Unknown. Later conflicts preserve immutable historical receipts/totals while explicitly exposing unknown identity; they are not spendable current balances.
- The new account-context fields/helper are private production interfaces. Added fixtures are inside normal test modules; no production test-only setter, forced proof flag, quota bypass or synthetic financial state injection was found. None/economics-disabled and read-only account modes retain the old funds invalidation/snapshot logic. Their new private context cannot enable trading, fees or reports without economic opt-in.
