## Material findings and implementation response

1. **Normal user fills currently miss the economics fee path (open at inspection).** The real fixture helper in tests/entropy_account/execution.rs::send_fill emits only channel=user, data={fills:[...]}. The economic raw parser accepts only the exact funding variant on user/userEvents; this fill variant becomes Unknown. In execution.rs the owned accepted-fill fee hook requires economic_source_clean, so a valid original user fill can generate the native Filled/commission while report actual_fee_usdc remains zero. The newly added actual_owned_fill_fee_reporting_never_applies_a_second_native_commission case expects -0.001 and exposes this mismatch. Root and both implementers were notified. The minimum production fix is strict raw user/userEvents fills support with the existing exact fill parser and verified private-stream account identity, preserving rejection of mixed/extra-key, duplicate-key and numeric financial envelopes. Extend raw startup validation to the same actual source variant. Adding an echo frame only to the fixture would conceal the normal-path defect.

2. **QueryAccount recovery followed by unconditional historical replay closed readiness repeatedly (narrow mitigation now inspected).** The current helper history_requires_invalidation reparses the actual body and consults phase-A observations, not report receipts/totals. Only an identical strong local key and financial digest with exact io instrument attribution may preserve an independently re-established account proof. A new key, changed payload, weak/Unknown, wrong scope/epoch or a tainted store still requires closing it. This permits the first new funding response to close proof and a subsequent independent current recovery to remain open during identical replay. Persisting B is irrelevant to this decision, including when phase A has not yet been consumed.

   The limitation is explicit: all account-wide non-funding ledger rows have null dex/instrument and cannot take that exception. A fixed history window containing such a row continues to close readiness on every query. Weak/Unknown/conflicting facts also retain the closed boundary. If broader availability is required, history must precede a completely independent later account/metadata/owned recovery, with actual fresh source times and captured epoch/revision fencing; receipts or report totals cannot reopen it. The present history helper records timeout/incomplete coverage and invalidates account/execution but returns Ok after coverage persistence. Reordering it without an explicit Incomplete/Error result could accidentally mask that failure. Root has this finding and the choice of limited replay exception versus reordered recovery.

3. **Checkpoint raw-to-normalized and consumer completeness gaps were found and a source fix is now visible (not executed).** Earlier load checks could accept a recomputed normalized amount/digest/checksum inconsistent with retained raw amount, or a recognized observation marked consumed with no receipt. The new ScopeEvidence records detached actual owner, io mode/token/trust/epoch and verified instruments. validate_raw_observation now reparses exact item lexemes and checks financial facts, keys, effect buckets, quality and ownership; WS original owner/channel is checked. Consumed unconflicted strong observations require matching immutable receipts, while unresolved consumed observations require an explicit unknown disposition. Three tamper cases have been added, awaiting root compilation. This proves internal semantic consistency; a checksum is not an authentication or external venue-signature claim.

4. **Malformed typed frames could still reach native Value-based projection; the narrow gate is now visible (not executed).** The bridge constructs the original raw frame before typed decode with legacy_parse_succeeded=false, and sets true only on the actual typed parser success. The actor now requires it for #101 owned projection and the accepted-raw fee hook. Numeric string-schema failures and duplicate known fields must remain raw -> Error -> ingress marker, with no native projection. A valid legacy fill on a channel not yet supported by economics remains distinct from a malformed financial payload; unknown!=0 alone is not an adequate global legacy projection gate. The actual malformed-owned-fill peer is required before closing this finding.

5. **Repeated full HTTP/WS envelope copies were identified and the shared representation is now visible (not executed).** The implementation now uses immutable raw_envelopes keyed by raw hash and per-observation references, plus Arc-backed parse staging. Rows retain exact item lexemes. Store validation checks byte/hash/reference bounds and rejects missing/unreferenced envelopes. The 500-row allocation/size test is source only at this stage.

## Other reviewed boundaries and honest limits

- Exact decimal strings are parsed without JSON Value numeric normalization; numeric literals are preserved as raw Unknown. Checked aligned-scale arithmetic rejects overflow and avoids rounded report sums.
- Funding uses the actual owner/network/hash/time/coin local composite, excluding money from the key. Same key with changed financial facts conflicts. Ledger participants/tokens do not manufacture separate unique cash identities inside the same hash/time effect bucket. Weak WS deliveries remain distinct observations without recognized cash.
- Raw actual fill fee recognition uses coin/tid plus exact financial digest. Ownership/native durable application are separate; native_applied remains Unknown. Phase B never applies a native fill or balance debit.
- Late conflict after a prior B commit marks the relevant old consumed observation unknown while preserving the immutable historical receipt and historical total. That total must not be represented as currently undisputed spendable cash. financial_identity_complete and unknown observations must expose the conflict. The label 'unresolved observations excluded' should not conceal amounts consumed before a later conflict.
- The store uses a persistent exclusive owner sidecar, identity marker, checksummed full checkpoint, same-directory temporary write/sync/replace, and monotonic semantic validation. Commit failure taints the current runtime. A rename followed by sync error must remain a failed/tainted call even if a later restart discovers the new valid committed file; B replay cannot add a second recognized contribution.
- Coverage retention is cumulative: history_max_pages*3 is the lifetime coverage-row cap, rather than merely a per-query page limit. Startup, replacement-stream gaps and repeated queries consume it. Observation/receipt/file limits also intentionally end a finite run. Exhaustion needs a preserved prior checkpoint, explicit closed diagnostic and zero new action proof; no unbounded expansion is implied.
- HTTP policy body size is checked after the existing finite transport has received the body and before economic array materialization. It is not a smaller transport-level streaming cap. Actual response-completion received_ms is captured before waiting for the extra per-item quota. Preserve this scope in acceptance wording.
- Current raw/outbound actor queues are unbounded existing channels. Per-frame/checkpoint/event retention bounds do not establish a global process-memory bound against arbitrary continuous input. Any eventual claim of bounded pending ingress needs an actual queue/backpressure limit or a narrower acceptance statement. No account write bypass was inferred from this limit.
- No-economics default paths must be checked against the final source: optional ABI suffix, constructor validation before secrets/I/O, no additional economic subscriptions/HTTP requests, and no economic projection or factory diagnostics accidentally attached to another client. Native diagnostics use Weak ownership and the live client owns the lease.
- Official history termination establishes only finite requested-window coverage. Venue retention, global hash uniqueness and real account economics remain unobserved. No source of financial trust is manufactured from a local receipt.
