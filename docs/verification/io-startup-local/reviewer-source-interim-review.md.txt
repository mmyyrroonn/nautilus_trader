## Blocking finding and correction pending final freeze

The first boundary compared account revision across the history requests. In `src/account_scope.rs::observe_ws`, accepted same-position private financial changes update `ws_facts` and receipt/source timestamps without incrementing that revision. The delayed private_funds case can therefore retain the old account revision with newer private financial input. This is a genuine incomplete asynchronous fence, not evidence of a flaky test or a generic cold-cache capability.

Root accepted this finding. The current working source adds `PrivateIngressState::received_sequence()` and captures it under the existing ingress lock in `IoStartupBoundary`; both the refresh boundary and final boundary compare the exact sequence as well as generation/epoch. It additionally compares the detached private-funds witness and final account snapshot. This conservatively refuses even a fully applied identical private message during the observation group, including messages sharing a millisecond timestamp. Overflow already sets the ingress failure state and connection reset changes generation. The final report is constructed inside the ingress/account/execution/cache critical section without an await. This addresses the identified mechanism in source, but the changed source still needs final freeze and actual rebuilt tests.

The other surprising case used `100.00000001` as an unrepresentable native USDC balance. Native USDC precision is eight, so that value is representable. The current test now derives one extra decimal digit from `Currency::USDC().precision` and asserts the native Money roundtrip is unequal before using it. Three old-journal tests attempted to read an exclusively locked file on Windows and are being corrected to stop/drop first. These are test defects; their original failures are preserved.
