# Independent selected chronology barrier review

Source identity and UTC are in `reviewer-native-chronology-barrier-source.json`. Review is source-only; no Cargo, builds, installs or product/test edits were performed. The parent's Clippy pass is author evidence, not a reviewer execution result. New peer tests and final wheel are pending.

The two previously identified emission bypasses are closed in the reviewed source. `StreamState.selected_chronology_debt` defaults false and has only true assignments, with no reset/clear. Session start changes the start/checkpoint but does not clear this debt or the delivered trade frontier. `has_recovery_debt` includes it. Diagnostics, snapshot publication, final Ready transition and new-risk admission check this combined debt under the normal state/readiness ordering.

All actual order/fill execution reports share the single `try_send_execution_report` in `emit_order_evidence`. Its early guard refuses existing sticky debt before any await. Its final state-write critical section checks sticky debt again, and checks each fresh nonduplicate fill's event time against the symbol's monotonically retained delivered frontier. It marks the order/trades pending and degrades readiness before releasing the state lock. The same lock covers successful channel send, frontier/confirmed-fill bookkeeping, and remaining-debt invalidation. Targeted order recovery, HTTP compensation and WebSocket order handling all use this central path. A concurrent hold during REST awaits therefore cannot be overwritten by a later send/Ready publication.

Whole-order recovery groups are sorted by earliest actual fill time, with intra-group chronological sorting. Selected overlapping/tied groups are held before any group for that symbol is emitted. Sticky debt blocks subsequent single-order repairs; a late B(T2) after delivered A(T1,T3) is also held at the final emitter frontier. The refusal is intentionally conservative and lasts for this client lifetime. It does not establish native cache adoption, durable restoration, strategy ownership or historical PnL correctness. Default None gains deterministic simple open/close ordering but does not certify arbitrary interleaved multi-order economics.

One remaining consistency recommendation was sent to parent: `advance_history_checkpoint` should itself refuse sticky debt under its state write lock. Existing callers check pending IDs using a separate earlier read lock, permitting checkpoint movement if another task introduces debt in between. This cannot restore Ready because the sticky field remains, but conflicts with a strict checkpoint-preservation claim. Likewise use combined `has_recovery_debt` for inferred-flat and final compensation diagnostics to keep the explicit chronology debt represented even if future bookkeeping changes pending markers.

No additional Ready/emission bypass was found in this focused source review. Actual new peer tests, replay regressions, final source-executable binding and wheel ABI/app native cases must pass before acceptance. Kernel isolation, funding, whole-account flatness, durable cold restart and mainnet remain unproven.
