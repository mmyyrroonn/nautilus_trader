The bounded diagnostic series retained five passing attempts and this failure. This confirms the report-order mechanism; the attempts are not retries to accept a flaky result.

First proposed fix sorts each group's trades by `(time, id)` and groups by earliest time, and rejects overlapping/tied selected-mode groups before emission. Read-only follow-up found two remaining safety gaps, sent immediately to parent:

1. Refusal notes pending OIDs/TIDs and bails. On the next compensation, those OIDs enter `pending_orders_before`. `compensate_orders`' targeted pending loop directly invokes `emit_order_evidence(..., Vec::new(), false)` without checking the chronology refusal/Unreliable coverage. The resolver can retrieve and publish each order separately, bypassing the refusal and consuming the debt. Chronology debt needs an explicit central emission barrier that cannot be repaired by a per-order fetch.
2. The interval guard uses only `missed` groups. If A's T1/T3 fills were delivered first and B's T2 arrives later, the next batch contains only B and passes an empty pairwise check. A selected-mode central guard must also account for already delivered event-time frontier/lineage, including targeted resolver and WebSocket emission; a conservatively retained Unknown is preferable to retroactively claiming global chronology. Existing `AppliedTrades.last_ts_ms` records actual delivered time and can support a strict conservative frontier; its lifecycle and bounded-cache behavior must not allow evicted metadata to reset the authority.

No repaired-source test result is claimed here. Both gaps remain findings against the first patch until parent freezes the revised source for review and actual testing.

For each unchanged test run, capture the received report sequence with venue order ID, side, reduce-only, trade IDs, trade timestamps, and positions after each engine reconciliation. Compare current and clean main with the exact same recorded Cargo argv/profile/features/toolchain and executable SHA. If traces confirm SELL-before-BUY, production must provide a deterministic history replay contract or conservative holdback for unrepresentable order overlap. Sorting only test events would conceal the adapter defect. Sorting bundles by earliest trade solves the simple one-fill open/close case but does not generally solve interleaved multi-fill orders: A(T1), B(T2), A(T3) cannot be represented by whole-order sequential bundles in true chronology. Preserve exact real IDs/fees, unknown coverage and exactly-once delivery while choosing a valid bounded solution. Run a deterministic reverse-input and multi-order chronology regression plus both package combinations; do not skip/weaken the flat assertion.
